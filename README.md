# توقّع (Pitchlab)

تحليلات وتوقع مباريات الدوريات الأوروبية الخمس الكبرى + الدوري الكوري — عربي كامل RTL.

الاحتمالات مشتقة من نماذج إحصائية شفافة على نتائج حقيقية، وكل رقم قابل للتتبع إلى نموذجه
ومصدره. `/accuracy` يعرض دقة النموذج على بيانات لم يرها أثناء التدريب.

## النماذج (ensemble-v2)

| الإشارة | الوزن | المصدر |
|---------|-------|--------|
| Dixon–Coles + تلاشٍ زمني (MLE عبر SciPy) | 0.42 | نتائج آخر 5 مواسم |
| Pi-ratings ديناميكية (هجوم/دفاع) | 0.18 | نفس النتائج |
| Elo بهامش الأهداف | 0.18 | نفس النتائج |
| فورم آخر 5 مباريات | 0.10 | نفس النتائج |
| سوق المراهنين (بعد إزالة الهامش) | 0.12 | `AvgH/D/A` في CSV |

ثم **temperature scaling** معاير على walk-forward (حدود `0.5–4.0`)، ثم تُوفَّق مصفوفة النتائج
مع 1X2 المعايَر حتى تكون الخريطة والأسواق (BTTS / أوفر-أندر / xPts) متسقة مع الشريط المعروض.

الحد الأعلى واسع بقصد: دوري بلا إشارة تخرج له حرارة عالية فتتسطّح احتمالاته نحو `33/33/33`
بدل أن يُثبَّت على ثقة لا يملكها. الحرارة المشبعة عند الحد هي نفسها إشارة قراءة: النموذج
يقول «لا أعرف» بدل أن يخمّن.

## البيانات

- نتائج تاريخية: [football-data.co.uk](https://www.football-data.co.uk/) — تُحدَّث للموسم الجاري في كل مزامنة
- مباريات مجدولة: [football-data.org](https://www.football-data.org/) عبر `FOOTBALL_DATA_API_KEY`
- الدوري الكوري: ويكيبيديا (تقويم سنوي)
- الشعارات: TheSportsDB، تُخزَّن محلياً في `public/crests`

المواسم تُشتق من التاريخ (`historicalSeasons()`)، فلا تتقادم القائمة مع مرور السنة.
بدون مفتاح API تعمل الواجهة على النتائج التاريخية وحدها ولا تُعرض مباريات وهمية.

**الشعارات:** الملف المحفوظ على القرص يفوز دائماً على الشبكة — فبلا هذا كان تقييد
TheSportsDB يستبدل مساراً محلياً برابط خارجي في كل مزامنة. وجولةُ استكمال تسأل عن
الأندية الهابطة (لا ترد في قوائم API الحالية) مرة واحدة ثم تحفظها. النادي الذي يبقى
بلا شعار يظهر بأول حرفين من اسمه، لا برمز عام.

## التشغيل

يتطلب Node ‏22–24 (`.nvmrc`) — الوحدة الأصلية `better-sqlite3` تُبنى لنسخة Node التي تثبّت بها،
واستعمال نسخة أخرى لاحقاً يعطي `NODE_MODULE_VERSION mismatch`؛ عندها شغّل `npm rebuild better-sqlite3`.

```bash
cp .env.example .env          # ثم ضع FOOTBALL_DATA_API_KEY

python3 -m venv .venv
.venv/bin/pip install -r requirements.txt

bun install
bun run pipeline              # مزامنة المصادر → SQLite → تدريب وتوقع
bun run dev                   # http://localhost:3000
```

| الأمر | الوظيفة |
|-------|---------|
| `bun run sync` | تنزيل المصادر إلى `data/pitchlab.db` |
| `bun run sync:crests` | تحديث الشعارات فقط |
| `bun run fit` | تدريب النماذج وكتابة التوقعات |
| `bun run pipeline` | الاثنان بالترتيب |
| `bun run check` | فحوص المنطق + فحص الأنواع + eslint |
| `bun run dev` / `build` | تشغيل / بناء |

لإعادة بناء القاعدة من الصفر: `rm -f data/pitchlab.db*` ثم `bun run pipeline`.

| المسار | الوظيفة |
|--------|---------|
| `/` | المباراة التالية + الجولة القادمة (حصة لكل دوري) + آخر النتائج |

## حدود معروفة

- الدقة الإجمالية على walk-forward ≈ 0.47 لـ 1X2، وهو مستوى طبيعي لثلاثة احتمالات؛ لا يُقدَّم كضمان.
- الدوري الكوري عيّنته أصغر ولا إشارة صالحة فيه: حرارته تشبع عند الحد فتخرج احتمالاته
  مسطّحة عن قصد. اقرأها كـ«لا أعرف».
- الفرق الصاعدة حديثاً بلا نتائج في القاعدة تبدأ من `Elo 1500` وقيم بَدئية؛ صفحة المباراة
  تقول ذلك صراحةً، والرقم أولويّة أوّلية لا قراءة معايَرة.
- صفحة الدوري تعرض نافذة (40 موعداً + 20 نتيجة) لا الموسم كاملاً — الموسم الكامل كان
  يشحن ميغابايتات لكل زائر بلا أن يقرأها أحد.
- التوقعات تُبنى وقت `fit` ولا تتفاعل مع أخبار الإصابات أو التشكيلات.
